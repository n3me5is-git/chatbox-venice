# Chatbox Venice 1.32.1

Native function calling in an E2EE chat now encrypts non-empty text returned by tools before sending it back to the model. Local/MCP/search results use the encrypted content channel; native definitions, names, call IDs and arguments remain visible to Venice. Existing model capability checks, tool permissions, media approvals and receipt verification settings still apply.

The native-tool consent dialog explains this boundary in English and Italian. Empty/null content and pending call IDs are preserved, and earlier tool history stays inside encrypted text. The separate encrypted-text tool mode continues to encrypt definitions, calls and textual results. This change was informed by the [AxLabs native-tool implementation](https://github.com/AxLabs/venice-e2ee/commit/7b4e6528f7f870402224bc887de06f0952f7f575).

## Validation

Focused tests use the real AI SDK and a simulated enclave to complete native tool/result exchanges with both strict and explicitly compatible receipts. They decrypt the returned tool content at the simulated enclave and check that its plaintext is absent from the request, while public call metadata survives. Transport tests cover buffered replies, parallel results, text-part normalization and empty/null content. UI tests check the updated consent; the existing localization, functional, browser and packaging checks run in Actions.

## Privacy limits

This does not repair the independent live receipt-hash mismatch, change the selected receipt policy, or hide arguments from the service executing a tool. Compatible receipts still provide reduced independent payload assurance. Full model hardware/software verification and physical-device biometrics are outside these tests. See [secure receipt verification](../venice-secure-receipts.md).
