# Chatbox Venice 1.31.0

This release improves image workflows, makes model costs clearer and repairs live E2EE interoperability with an explicit receipt-verification choice.

- Crop image references locally in chat image approval, native Image Creator and Venice Studio image/video references. Use touch dragging, aspect ratios or percentage coordinates. Crops preserve transparency and the original file; protected-library source scope follows the cropped attachment.
- Open **Venice Studio → Image tools** to remove a background or upscale an existing image at 2×/4× with an added-detail control. Upload from the device or local library, optionally crop, then explicitly confirm processing. Each operation saves a new local creation and supports protected output. Failed paid requests are not replayed automatically. Native output uses the encrypted media store.
- Existing image history provides remix/edit, batch count and painted-area editing with percentage comment points. Painted-area editing uses Venice's compatible image-edit model followed by local mask composition; this is not a new native server mask endpoint. Public/protected library controls and re-authentication remain available.
- Model cards show readable USD/DIEM rates and billing units, including text/embedding tokens, TTS characters, audio seconds and generation/quality tiers. Video cards request an estimate only on explicit action and show its average per output second. Missing catalog prices are marked unknown, never free.
- Fix Phala quote padding and add **Compatible gateway receipts**, off by default with separate consent. Live Venice rewrites bytes between the app and attested gateway; its valid signature hashes cannot always be matched to the outer request/response. Compatibility retains E2EE, fresh attestation and attested-signer verification while trusting provider-reported payload hashes. It does not provide independent payload/replay binding. Strict verification remains the default. See the [investigation and policy guide](https://github.com/n3me5is-git/chatbox-venice/blob/main/docs/venice-secure-receipts.md).
- New controls and messages have explicit English/Italian resources, with English fallback for other supported locales.

## Verification

Actions run TypeScript, functional/security tests, React interactions, signing checks and mobile/desktop Chromium before packaging. Browser checks cover actual crop pixels and alpha, touch dragging, quote selection/consent and image-processing requests. Image processing is simulated without paid image API calls.

Authorized live tests used a runtime-only temporary key: text, a local tool, E2EE text, an encrypted tool/result cycle, short TTS/transcription, five-second music and one five-second economical video. Music/video were saved locally and their remote cleanup endpoints returned success. The client cannot independently verify provider retention. Full model coverage and physical-device biometrics remain outside these tests. The app's build environment was not installed locally.

Personal-signed Android APK and Windows x64 setup remain available from [this fork's releases](https://github.com/n3me5is-git/chatbox-venice/releases/latest). Existing Android signing identity and app data format are retained.
