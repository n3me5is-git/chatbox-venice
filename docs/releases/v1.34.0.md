# Chatbox Venice 1.34.0

## File editing and Markdown export

- Managed text files and writable Work files retain the text editor. Text attachments/read-only resources offer **Edit a copy**, preserving the original and saving an editable managed file under `edits/`.
- Markdown's rendered viewer now exports **PDF** and **single-file HTML**, including a table of contents, heading links, tables, local images, Mermaid diagrams and LaTeX fonts.
- HTML embeds its preview assets and requires no app, CDN, Mermaid runtime or network connection. External images retain their explicit preview opt-in. Links to other documents remain links; those target files are exported separately.
- Windows generates PDF in an isolated local Chromium renderer and uses the existing save flow. Android opens the system print sheet: choose **Save as PDF**. The print views have no script execution, native file access, provider credentials or network loading.
- Native image/audio/video/HTML previews remain available. Desktop can use its native PDF viewer. No Office viewer or cloud document conversion was added.

## Global speech models and chat controls

- Configure separate recognition and synthesis models in **Settings → Default models**. Load the audio catalog, choose a model, select an available voice and recognition language, and open Venice's existing model card for supported options and pricing.
- The chat microphone records locally, then **Transcribe into draft** uses the selected global STT model. It appends editable text, preserving the current draft. It never automatically sends the prompt.
- **Read aloud** in an assistant reply's action row uses the selected global TTS model. It sends readable text from that reply, excluding code blocks, raw HTML, thinking and tool arguments. A local player opens on demand.
- Supported direct audio endpoints are OpenAI-compatible, using Venice, OpenAI, Groq or a custom compatible configuration. The selected provider/model must implement that endpoint. Queued advanced Venice speech remains in Studio. No model or fallback provider is selected automatically.
- Errors never automatically repeat a paid speech call. Closing, backgrounding, changing relevant configuration or locking stops the active recording/player and cancels pending work. Reply audio is transient and is not automatically added to the library.

## Privacy behavior

- **Private/TEE chat + private speech:** allowed via HTTPS.
- **Private/TEE chat + non-private, anonymous or unknown speech:** disabled. Tapping the control explains why; no audio upload or synthesis request occurs.
- **E2EE chat/model + private speech:** a warning explains the HTTPS boundary and requires **Continue for this request**, every time.
- **E2EE chat + non-private/unknown speech:** blocked, with no override.
- Speech does not implement the text E2EE handshake. Catalog privacy is a provider claim, not proof of encryption. Cached claims are bound to the endpoint/key; changes require catalog reload. Configuration, permissions and project access are rechecked before sending and before returning content.

## Validation and compatibility

- TypeScript, existing regression suites, new speech request/privacy tests, file editor/export tests and native PDF isolation tests run in Actions.
- Browser checks use the production speech controls/client with simulated services, a real recorder fed by a synthetic microphone and a real WAV decoder. They verify editable drafts, refusal without API calls, per-request E2EE consent and cleanup on lock.
- The actual exported HTML is reopened offline and printed to a real PDF for visual inspection. Android native code is compiled; existing Keystore runtime tests also run on API 34/35 emulators. These checks do not use a real microphone device or paid provider inference.
- Existing Work tools, Studio approvals, text E2EE/MCP calling and media storage behavior are retained. English and Italian strings/changelogs are included, with English fallback for other app locales.
- Windows x64 setup and Android APK are built in Actions. Android retains the private signing identity; personal installation does not require a Play Store developer account. Windows remains unsigned.
