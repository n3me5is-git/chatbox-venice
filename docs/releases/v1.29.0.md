# Chatbox Venice 1.29.0

This release fixes the mobile Venice workflows reported after 1.28.1 and makes the local media library accessible from the sidebar.

## Fixes and improvements

- Balances use the inference-key rate-limit endpoint and parse both USD and DIEM, including zero balances. An administrative API key is no longer needed to display credit.
- Android biometric key operations authenticate before supplying associated data to the cipher. Newly created keys avoid the known unlocked-device-required problems on Android 12–14; existing key aliases and encrypted files are preserved. Authentication errors retain a diagnostic code.
- Mobile sheets use one scrollable body and a consistent focus scope. Project protection and Venice selectors retain touch selections. Android Back dismisses the top registered menu, sheet, preview or image viewer before navigating.
- Image prompts use Enter for a newline. Generation starts from the explicit button. Advanced image controls open in a separate settings panel. Images keep their complete aspect ratio, and mobile image actions sit below the image.
- The sidebar library browses local files with image thumbnails, selectable previews, content categories and separate public/protected areas. Upload offers Device or Local library from the same control. Images without a saved thumbnail are decoded one at a time to create a small in-memory thumbnail; originals are loaded only for selected previews or attachments.
- Protected previews require authentication for their current view even when a running task already has the scope key. Public-to-protected moves act on the owning creation where available. Image history has visible creation actions and long-press access. Studio history follows the selected content category.
- Provider configuration and Studio model menus show categories and catalog privacy, uncensored, TEE and E2EE badges. Provider lists expose the Hide Chatbox AI in selectors preference. Model details present readable prices/options, a native documentation WebView on Android, a separate sandboxed browser window on Windows, and external-browser/Chrome choices.
- Model search and the Chatbox retrieval tool have independent controls. Venice model search offers automatic/always/off behavior and backend/citation settings. The global tool uses Venice `/augment/search` with Brave, Google or Exa. Backend-specific automatic search tools survive active-tool preparation.
- Queued ElevenLabs and Seed speech models appear under Voice, while retaining the audio queue/retrieve/complete API transport. Music and sound effects remain separate. Controls follow catalog support rather than sending unsupported defaults. Queued speech quotes include character counts where required.
- Venice approvals are in conversation settings. Fork strings have explicit English and Italian resources; other supported languages retain English fallback. Italian release highlights are available in the app.

## Verification and limits

Actions run TypeScript, functional/storage/security tests, UI tests and Chromium desktop/mobile interactions. Android Keystore tests run production key creation, reload, authenticated-encryption round trips and tamper rejection on API 34 and 35 emulators. Physical fingerprint sensors, device codecs and paid Venice inference still require target-device verification. Browser evidence exercises production controls inside the shared mobile panels, with synthetic API data and device-key wrapping.

The current Venice music API does not expose an audio-reference remix input. Catalog privacy/uncensored badges describe provider declarations; they do not imply that E2EE is active. Project locks still control in-app access rather than encrypting the ordinary chat database. Library backups contain media and library metadata; conversation backups are separate.

See [testing](https://github.com/n3me5is-git/chatbox-venice/blob/main/docs/fork-testing.md), [local security](https://github.com/n3me5is-git/chatbox-venice/blob/main/docs/local-security.md) and [downloads](https://github.com/n3me5is-git/chatbox-venice/releases/latest). Android retains its existing personal signing identity; Windows installers are unsigned.
