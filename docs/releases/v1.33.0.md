# Chatbox Venice 1.33.0

## Session resource explorer

- Open **Files and resources** from the chat header. Desktop uses the right sidebar; phones use a scrollable sheet.
- Browse managed files, attachments, existing Work outputs, chat artifacts and this session's generated images/audio/video in a tree, without preloading the media library.
- Preview Markdown with GFM tables, LaTeX, Mermaid, a table of contents, local images and relative file links. Remote Markdown images require opt-in. HTML previews are isolated and offline.
- Create, import, edit, export or delete one resource. Deleting one image preserves the other images in its batch. Deleted bytes may no longer open from chat or library references.
- Managed working files stay out of the library. Explicitly mark a final document/output as a deliverable to publish it there. Scripts are not automatically published.
- New managed files and their index use authenticated encrypted chunk storage, project access controls, and a dedicated encrypted workspace backup/restore flow. Existing Work directories retain their original format and tools.

## Local agent workspace

- `session_file` lets an enabled Agent/Work chat list/read/search/import/write/delete managed files and mark deliverables.
- `session_js` executes isolated JavaScript against explicitly selected managed inputs, with no network, shell, app database or provider credentials.
- Optional `session_python` uses a pinned, SHA-256-verified Pyodide runtime and curated packages. Download/install is explicit; execution is offline in a disposable worker. No system Python or local build environment is needed.
- Successful output changes commit together. Runtime failure, cancellation or conflicting edits do not publish execution changes. Code and file quotas are enforced. Python's WASM heap is capped at 256 MiB; browser/loader memory is additional.
- The existing Work tools and terminal behavior are preserved; no new OS terminal was added.

## Desktop MCP server

- Opt-in authenticated Streamable HTTP server on `127.0.0.1`, scoped to one selected chat.
- Separate grants for file reads/writes, isolated execution, text models, Venice Studio, web search and forwarding other configured MCP tools.
- Text-model calls use explicit messages, inherit chat privacy and ask for approval by default. Automatic paid calls need a separate grant.
- New token per sharing run; stop, lock or app exit revokes access and cancels pending requests. Browser Origin and unexpected Host headers are rejected. Known configured credentials are redacted from outbound responses.
- Only share with trusted clients: authorized content is decrypted for them. E2EE to Venice does not control an external agent's subsequent use of that content. The Android app does not start a persistent MCP HTTP server.

## Validation and distribution

- TypeScript checks, deterministic storage/execution/privacy/MCP tests, real MCP SDK client tests and simulated desktop/phone interactions run in GitHub Actions.
- Real browser checks execute QuickJS and Python/NumPy; local Edge probes also verify Python network blocking and its memory ceiling. Existing Venice UI/privacy tests remain included. No paid provider request or company data is required by these checks.
- English and Italian UI resources and changelogs; new strings fall back to English in other app languages.
- Windows x64 setup and signed Android APK are built in Actions. Android retains the existing private signing identity; Windows remains unsigned for personal use.
