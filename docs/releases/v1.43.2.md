# 1.43.2 — Explicit reference model selection

- Image Creator and the image section of Venice Studio show the selected endpoint, privacy badges and catalog price beside image attachments, with a dedicated compatible-model picker.
- Manual model selections are preserved. An incompatible manual choice blocks generation and asks for a compatible model; it is never silently replaced. Automatic variant selection can be enabled or disabled in the attachment controls.
- Automatic selection only switches to an exact available image-family counterpart when both endpoints declare the same privacy classification and have matching TEE/E2EE and filtering flags. Different or missing privacy metadata requires an explicit model choice, including changes toward a more private variant. Provider privacy filters still apply independently.
- The live public catalog checked on 11 November 2026 contained 31 image/edit pairs. `qwen-image` was classified as `anonymized`, while `qwen-edit-uncensored` was classified as `private`. The family name is not treated as a privacy guarantee. Catalog classifications can change.
- Reference/editing badges and input limits appear in native image pickers, Venice selectors and model information badges. Missing privacy is explicitly labeled as undeclared. Long names and badges wrap on narrow screens.
- Style-reference generation is labeled separately from source-image editing. GPT Image 2.5 Flare/Sunburst and Seedream reference editing use their catalog `-edit` endpoints; style-reference models keep their generation endpoint. The API can expose separate entries even when the Venice web interface presents one family.
- Venice image approvals in chat use the same policy, with a direct reference-model selector and a disabled Generate action until the selected model accepts the attached images. The remix/edit/inpainting dialog retains its explicit compatible-model selector.
- New UI strings include English and Italian, with English fallback for other supported languages.

Request payloads, image storage, encryption and approval policies are unchanged. The six successful live editing generations recorded for 1.43.1 remain the editing baseline. A separate live request with `krea-v2-medium` and two style references returned HTTP 200 and a valid PNG using `/image/generate`; it used the production request builder and synthetic images. Selection, privacy boundaries and UI interactions are covered by additional regression tests.
