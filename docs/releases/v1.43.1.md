# 1.43.1 — Image references and local library reuse

- Adding references selects the available editing variant of the same Venice image family before generation. The displayed model, capabilities and price refer to the actual variant being approved. This applies to Image Creator, the image section of Venice Studio, and Venice image approvals in chat.
- Selecting an image family in provider settings also exposes its corresponding reference endpoint, while preserving privacy filters. Separate text and editing entries show their operation and input limit.
- Reference requests use `/image/multi-edit` with `modelId` and an `images` array. Genuine style-reference models retain their generation endpoint. Model-specific limits are enforced; the old 14-image UI ceiling no longer truncates 16-input editors.
- The remix/edit/inpainting dialog accepts additional reference images from the device or local library, with optional cropping. Its model list accounts for the source image plus every additional input. Ordinary remix/edit reuses the source asset; inpainting alone creates the required cropped patch.
- Attaching an unchanged internal-library image reuses the existing asset after SHA-256 comparison and current access checks. Canceling or clearing the draft does not delete that asset. Cropped images retain their protection scope and their own bytes. Identical uploads in one draft are deduplicated, and intermediate reference files are excluded from the media library.
- Reference imports are read sequentially to limit peak memory. Generation waits for imports to finish; a failed attachment shows its error and blocks submission instead of silently sending a request without that image.
- “Use selected content” is available above and below the library grid.
- OpenAI Sub Unofficial sends multiple references through both supported image transports. The previous four-input restriction is replaced by a local ceiling of 16 and a combined request-size guard. This ceiling is not a guarantee that an undocumented endpoint or every account accepts that many inputs; server errors are preserved, without a provider fallback or automatic paid retry.

## Validation

Live requests on 11 November 2026 used the production Venice request builder and synthetic, non-personal reference images:

| API model | Reference images | Result |
| --- | ---: | --- |
| `qwen-image-2-1-turbo-edit` | 2 | HTTP 200, valid PNG |
| `seedream-v5-5-edit` | 2 | HTTP 200, valid PNG |
| `gpt-image-2-5-flare-edit` | 6 | HTTP 200, valid PNG |
| `wan-2-7-pro-edit` | 2 | HTTP 200, valid PNG with automatic aspect ratio |
| `minimax-h3-image-edit` | 16 | HTTP 200, valid PNG |

Wan rejected an initial explicit square ratio; its editing endpoint accepts `auto` only. Unsupported ratios are now rejected locally. No videos were generated. GPT subscription transport tests use simulated server responses; no live subscription-account test is claimed.

The public Venice catalog classifies Seedance as video and Seedream as image generation/editing. Image references are also supported by the appropriate Wan and MiniMax image variants; video variants are not substituted for image models.

See the [Venice image editing contract](https://docs.venice.ai/api-reference/endpoint/image/multi-edit). Subscription input-image handling was cross-checked against [image-use](https://github.com/leeguooooo/image-use).
