# Chatbox Venice 1.35.1

**Update both devices and create a new pairing code.** Sharing invitations now use CB2; earlier invitations are rejected with an upgrade message.

- Update Trystero to 0.26.0: fix idle owners offering a stale WebRTC description without candidates, fast rejoin bindings and the old preallocated 20-peer pool. This addresses a connection failure reproduced after the owner waits over one minute.
- Scan pairing QR codes live with the camera, or choose an existing QR photo/screenshot. Both paths decode locally, fill the code and require an explicit Join action. Android camera permission is requested only for live scanning; camera-less devices remain supported.
- Replace `[object Object]` pairing failures with readable transport messages. Distinguish WebRTC connection failure, invitation verification, secure-handshake timeout and an unresponsive owner/signaling path. Add Retry connection after a failed/disconnected attempt.
- Add optional TURN connection settings for restrictive networks, separate from signaling relay configuration. Credentials are temporary, excluded from pairing codes and not persisted. Relayed content retains the existing authenticated encryption and owner-admission requirements.
- Stop camera capture when scanning closes, the app locks or the scanner goes into the background. Explain denied permissions and retain image upload as an alternative.
- Add automated live-video/file QR decoding, actual direct/forced-TURN Chromium WebRTC, retry/structured-error tests and Android API 34/35 camera/data-channel runtime probes.

The reported connection failure on two physical Android phones on the same Wi-Fi has not been reproduced on those devices. This update exposes the underlying error for diagnosis; TURN is an optional networking fallback, not a confirmed explanation for that report. See the [pairing guide](../collaboration-troubleshooting.md).
