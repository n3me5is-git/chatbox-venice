# Chatbox Venice 1.32.2

Repairs MCP/function calling in encrypted Venice chats, including DeepSeek and GLM. Encrypted tool prompts use a dedicated `<venice_tool_call>` text envelope to avoid interference with backend-native tool parsing. Existing JSON/tag variants remain supported, and GLM's `function_calls/invoke/parameter` XML is recognized with bounded parsing and typed arguments.

Native mode also supplies tool instructions through the encrypted text channel. When a gateway returns a call in encrypted content instead of native `tool_calls`, the app reconstructs it after receipt verification. Native calls take precedence, so a call is not dispatched through both paths. This bridge does not change the selected privacy mode: native definitions, names and arguments are still public. Choose **Encrypted tool messages** to encrypt those as well. Consent explains this in English and Italian.

NEAR `provider_tee` signatures use `upstream_model:request_hash:response_hash`, whereas gateway signatures use two hashes. The verifier now recognizes that distinction, binds the upstream model to the current attestation and retains exact payload checks in strict mode. Explicit compatibility can accept the provider-signed hash format after validating its attested signer and request/model metadata. Compatibility is still off by default; it does not establish independent payload binding.

## Validation

Automated regression tests cover GLM XML, typed/parallel calls, malformed XML, duplicate parameters, quoted examples, schema failures, invalid signatures and mismatched upstream models/request IDs. Real SDK tests verify full encrypted result round trips and withhold execution on verification failures. A CI-built live driver exports the production MCP client so local probes can exercise actual stdio discovery/calls with synthetic records. Live results are recorded separately; neither CI nor the repository receives an API key.

The corrected CI bundle completed real E2EE MCP cycles on **DeepSeek V4 Flash, GLM 5.3 and GLM 5.3 Flash**, using the production MCP client, actual local stdio tools and random result codes checked in the model's final answer. Tests include automatic tool choice, negotiated and legacy MCP clients, nested objects, arrays, integers and booleans. GLM Flash also completed a native-mode cycle through the verified encrypted-content bridge. These calls used explicit compatible receipts. Temporary HTTP 429 attestation limits and GLM 5.2 HTTP 504 availability failures were retained as failed attempts, not counted as successes.

Actions passed **659 functional tests in 64 files**, the English/Italian UI suite and browser simulations before packaging. Paid media generation and a real company ERP were not used in these MCP probes.

## Limits

No plaintext retry, automatic receipt-policy change or automatic paid completion retry was added. External MCP/search services still receive the arguments needed to execute their tools. Model/backend availability and instruction following remain relevant. The independent live receipt-hash boundary and model hardware/software verification limitations are unchanged; see [secure receipt verification](../venice-secure-receipts.md).
