# Chatbox Venice 1.30.0

This release adds encrypted tool conversations and separates search controls while preserving existing provider and approval behavior.

- Opt in to **Tools in encrypted chat** in Venice provider settings. The default encrypted-tool transport carries definitions, calls and textual results inside E2EE using the attributed `venice-e2ee` text protocol. Calls execute only after decryption, response-signature verification and SDK validation.
- An explicit alternative enables native function calling with visible tool metadata on catalog-compatible models. Its warning explains the privacy difference. Native calls require signatures covering their actual data; failed verification never triggers a plaintext retry.
- Venice search now has its own per-chat pause switch and settings icon. Pausing retains the selected search mode/backend. **Do not search** greys out the switch. The global Chatbox search toggle remains independent and can be disabled during an answer.
- Optionally expose `venice_web_search_brave`, `venice_web_search_google` and `venice_web_search_exa` separately, alongside the global `web_search` tool. All Venice retrieval uses `/augment/search` directly. Repeated queries reuse results; failed tools and shared per-answer budgets prevent repeated network search loops.
- New-chat Venice profiles carry into the saved conversation. Enabling encrypted tools immediately refreshes Work/MCP availability. Search and privacy dropdowns keep mobile focus and handle Back before their containing panel. New controls include explicit English and Italian translations.

## Verification and limits

GitHub Actions run TypeScript, focused functional/security tests, React UI tests, signing checks and desktop/mobile Chromium interactions before building Windows x64 setup and the personal-signed Android APK. Synthetic enclave tests exercise the real SDK, encryption and signature checks through a complete tool/result cycle. Paid Venice inference, every live gateway's native tool signature format and physical-device biometrics are not covered by these simulations.

Search/MCP services receive the arguments needed to execute their tools. Provider-integrated search and multimodal inputs remain unavailable in E2EE text mode; client search tools are supported after consent. Media generation APIs still use HTTPS rather than the text E2EE handshake. Catalog privacy/TEE/E2EE badges describe capabilities, not proof that a connection uses encryption. Existing local storage and signing identities are retained.
