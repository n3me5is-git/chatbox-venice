# Release notes

Write `docs/releases/vVERSION.md` in English. Use a short title and up to eight concise bullets covering added features, fixed user-visible problems and necessary update instructions. Target 50–150 words; the publishing limit is 200.

Keep test counts, workflow runs, API probes, screenshots, source revision reports and implementation investigations in pull requests, Actions artifacts or technical documents. Release notes are for people updating the app.

The release publisher and historical-note synchronizer validate this format before publishing. Editing historical notes updates their GitHub release descriptions without replacing packages or moving tags. Verify the published descriptions after synchronization.
