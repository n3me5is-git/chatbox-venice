# Direct device transfer

Use **Send to another device** in a chat's menu. On the receiver, open the sidebar's sharing panel and select **Receive / transfer**. Scan the QR code with the live camera, upload a QR image, or paste its code. The sender must explicitly approve the receiving participant before any manifest or chat content is disclosed.

The transfer includes all conversation branches, the complete child-agent tree, session directories, intermediate files and generated deliverables. Media records are rebuilt with new local identities so in-chat image previews and audio/video cards can reopen local results. Provider credentials, device encryption keys, remote generation queues and execution authorizations are excluded. Imported filesystem execution and automatic multi-agent permissions start disabled. Select a receiving provider/account before continuing work if it differs between devices.

The receiver can name a new chat or replace a related local copy. Replacement creates a complete new tree and archives the previous root only after success; it does not merge divergent messages or overwrite the previous chat in place. Related copies retain a lineage receipt. SHA-256 and exact byte lengths determine which objects can be reused locally, including objects that moved. A three-way baseline highlights local modifications when a prior receipt exists. The receiver explicitly confirms replacement. There is no background bidirectional synchronization.

Files stream in bounded chunks with acknowledgements; each candidate is authenticated and checked against its declared SHA-256 before publication. The receiver encrypts assets with its own storage key. A persistent journal rolls back incomplete candidates after cancellation or a crash, or finishes publication after a committed transfer. Protected content is opt-in at the sender and requires an unlocked protected receiving project. Temporary outgoing snapshots and unpublished file assets are excluded from library backups.

Limits: 65 chats (root plus 64 workers), three child levels, 2,048 objects, 128 MiB per object, 2 GiB per offer, and existing per-workspace file-storage limits. Finish or stop active agents and text/media generation before preparing an offer. Paused remote media is copied as a local historical record; resuming an old paid queue on a different account is deliberately unavailable.

Transport uses the same pinned-owner ECDH/AES-GCM overlay and WebRTC DTLS as collaboration. Public Nostr signaling relays exchange pairing information, not chat plaintext. Invite codes are secret credentials; direct connections expose network addresses to peers. Optional TURN relays carry encrypted traffic and their credentials are connection-local. Transfer codes (`CBT1`) and live-sharing codes (`CB2`) are distinct. Transfers end on a manual app lock or app exit. The existing opt-in sharing background setting also covers active direct transfers.

Keep both apps open until the receiver reports completion. A successful local copy remains available if the final acknowledgement cannot reach the sender. A lost connection before publication leaves the old local tree intact; retry starts a new verified import.
